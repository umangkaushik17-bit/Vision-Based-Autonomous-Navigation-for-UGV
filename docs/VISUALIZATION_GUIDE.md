# Dynamic Navigation Visualization Guide

**Phase 13.17 Reference Manual**  
**Location of Artifacts:** `simulation/outputs/dynamic_visualization/`  
**Primary Tool:** `scripts/visualize_dynamic_tracks.py`  

---

## 1. Overview

This guide explains how to generate, inspect, and interpret the Phase 13 dynamic obstacle navigation visualization suite. The pipeline produces reproducible, publication-quality diagnostic plots and frame-by-frame animations directly from empirical benchmark telemetry logs without modifying production AI code.

---

## 2. Directory Structure & Canonical Artifacts

Artifacts are generated into `simulation/outputs/dynamic_visualization/`:

| Artifact Filename | Type | Description |
|---|---|---|
| `01_trajectory_xy.png` | Static Plot | 2D XY trajectory of UGV path, target goal beacon, obstacle historical tracks, and vehicle footprint. |
| `02_velocity_profiles.png` | Multi-Panel Plot | Commanded vs actual linear speed ($v$) and yaw rate ($\omega$) overlaid with behavioral state spans (`PROCEED`, `AVOID`, `WAIT`, `STOP`). |
| `03_clearance_vs_time.png` | Diagnostic Plot | Continuous minimum clearance to dynamic obstacles compared against safety thresholds ($0.35\,\text{m}$ E-Stop, $0.60\,\text{m}$ Caution Margin). |
| `04_prediction_fan.png` | Spatiotemporal Plot | Forward motion prediction waypoints and expanding $3\sigma$ Continuous White Noise Acceleration (CWNA) uncertainty circles at discrete horizons ($+0.5\,\text{s}, +1.0\,\text{s}, +1.5\,\text{s}, +2.0\,\text{s}$). |
| `05_dynamic_tracking.png` | Tracking Diagnostic | Multi-object tracking (MOT) trajectory vectors and Kalman-filtered obstacle speed evolution over time. |
| `06_engineering_dashboard.png` | 4-Panel Dashboard | Unified engineering overview combining XY path, velocity commands, safety clearance, and prediction fan in a single cohesive figure. |
| `07_avoidance_animation.gif` | Animated GIF | High-resolution frame-by-frame animated visual replay showing the complete closed-loop avoidance maneuver with HUD overlay. |

Subdirectories for canonical benchmark scenarios are organized under:
- `simulation/outputs/dynamic_visualization/B01/` (Open/flat baseline corridor)
- `simulation/outputs/dynamic_visualization/B05/` (Single dynamic obstacle crossing)
- `simulation/outputs/dynamic_visualization/B06/` (Multi-obstacle dynamic crossing)
- `simulation/outputs/dynamic_visualization/B07/` (Mixed static obstacles + dynamic crossing)
- `simulation/outputs/dynamic_visualization/B11/` (Perception sensor degradation & recovery)

## 3. How to Regenerate Visualizations

### 3.1 Single Scenario Generation (Default B05)
```bash
python scripts/visualize_dynamic_tracks.py \
    --telemetry simulation/outputs/phase16/telemetry/B05_single_dynamic_seed42.json \
    --output-dir simulation/outputs/dynamic_visualization
```

### 3.2 All 5 Canonical Representative Scenarios
```bash
python scripts/visualize_dynamic_tracks.py \
    --all-representative \
    --output-dir simulation/outputs/dynamic_visualization
```

### 3.3 Fast Plot Generation (Skip GIF Animation)
```bash
python scripts/visualize_dynamic_tracks.py \
    --telemetry simulation/outputs/phase16/telemetry/B06_multi_dynamic_seed42.json \
    --output-dir simulation/outputs/dynamic_visualization/B06 \
    --skip-animation
```

## 4. How to Inspect in RViz2

The existing ROS2 demonstration RViz configuration provides full interactive 3D inspection:

```bash
# In an active ROS2 Jazzy / Humble environment:
rviz2 -d simulation/rviz/judge_demo.rviz
```

### Key RViz Displays:
- **Global Path (`/planning/global_path`):** High-level route computed by global $A^*$.
- **Selected Local Trajectory (`/planning/dynamic_trajectory`):** Active best candidate trajectory generated by DWA.
- **Judge Markers & Telemetry (`/visualization_marker_array`):**
  - `dynamic_track`: 3D bounding cubes representing confirmed obstacle positions.
  - `pred_trajectory`: Red forward prediction path line.
  - `pred_time_label`: Timestamp annotations ($t+1.0\text{s}$, etc.).
  - `dwa_candidates`: Fan of candidate rollout paths evaluated by DWA.
  - `judge_hud`: Real-time on-screen status banner showing mode, speed, and clearance.
- **UGV Odometry (`/odom`):** Real-time vehicle pose and heading vector.
- **Dynamic Obstacle Odom (`/dynamic_obstacle/odom`):** True/estimated obstacle motion.

## 5. How to Interpret Diagnostic Plots

### 5.1 Trajectory Plot (`01_trajectory_xy.png`)
- **Blue solid curve:** UGV closed-loop motion from $(0, 0)$ to Goal $(4.0, 0.0)$.
- **Orange dash-dot curve:** Tracked dynamic obstacle path crossing the corridor.
- **Red dotted lines:** Forward predictions generated at key decision timestamps.
- **Verification:** Confirm that the blue curve deviates smoothly around the crossing point without sharp discontinuities or erratic jitter.

### 5.2 Velocity Profiles (`02_velocity_profiles.png`)
- **Top Panel:** Commanded linear speed $v_{\text{cmd}}$ (dashed black) vs realized $v_{\text{act}}$ (blue).
- **Bottom Panel:** Commanded yaw rate $\omega_{\text{cmd}}$ (dashed black) vs realized $\omega_{\text{act}}$ (magenta).
- **Background Colors:**
  - Light Green: `PROCEED` (nominal tracking)
  - Light Yellow: `AVOID` (lateral deviation active)
  - Light Blue: `WAIT` (zero forward speed, waiting for crossing agent)
  - Light Red: `STOP` (emergency deceleration)
- **Verification:** Ensure smooth speed deceleration when transitioning to `AVOID`/`WAIT` and absence of high-frequency velocity oscillations (chatter).

### 5.3 Clearance vs Time (`03_clearance_vs_time.png`)
- **Purple solid line:** Distance from UGV footprint to nearest dynamic obstacle.
- **Red dash-dot line ($0.35\,\text{m}$):** Lethal collision boundary. Clearance must **never** drop below this line.
- **Orange dashed line ($0.60\,\text{m}$):** Caution boundary. When clearance enters $[0.35, 0.60]\,\text{m}$, speed is automatically clamped.
- **Green dotted line:** Remaining distance to target goal.

### 5.4 Prediction Fan (`04_prediction_fan.png`)
- **Red circles:** $3\sigma$ spatial covariance bounds. Lookahead time $\tau \in \{0.5, 1.0, 1.5, 2.0\}\,\text{s}$.
- **Verification:** Circles expand monotonically with $\tau$ according to the CWNA model, guaranteeing conservative safety margins for distant projections.

## 6. Running Validation Tests

To ensure the visualization generator maintains schema validity and image encoding integrity:

```bash
pytest tests/test_visualization_pipeline.py -v
```

This verifies:
- Ingestion of single-mission and multi-mission schemas.
- Rejection of corrupted JSON and non-finite NaN/Inf coordinates.
- Generation of non-blank PNG images ($W \ge 800\,\text{px}, H \ge 600\,\text{px}$).
- Animated GIF frame count ($N \ge 5$) and dimension consistency.
- Correct handling of scenarios with zero dynamic obstacles.
